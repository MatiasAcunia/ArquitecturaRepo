# Systemic Escalation and Anti-Churn

## Purpose

Ensure repeated failures are corrected at their causal owner instead of producing endless local patches, Planner passes or new policies.

## Ordinary defect

An implementation/test/reviewer failure inside a valid charter remains I3-owned.

Typical response:

`diagnose -> generalized fix -> verify -> independent review -> continue`

No new campaign is required.

## Repeated failure class

When the same subsystem/failure class repeatedly returns:

1. stop incremental symptom mining;
2. identify the shared causal mechanism;
3. perform grouped hardening;
4. run an independent adversarial review;
5. reverify the complete affected obligation set.

Repeated difficulty alone still does not automatically transfer authority to Planner.

## Strategic invalidation

Return to I2 only when evidence shows a strategic condition such as:

- product objective changed;
- owner boundary is materially wrong;
- public/interface semantics must change outside allowance;
- canonical state ownership must move;
- current charter architecture is physically falsified;
- required external/client authority is unavailable;
- safety/integrity/currentness contradiction cannot be solved inside charter.

## Systemic escalation

Escalate to I1 when the causal defect is shared across projects/workstreams or belongs to the development system itself, for example:

- Planner churn;
- Campaign Leads repeatedly failing to absorb tactical work;
- stale bootstrap/currentness mechanics;
- duplicated global policies;
- defective shared runtime/controller;
- broken cross-boundary governance;
- systemic false-PASS routes.

## Causal-fix rule

A material issue that reappears after prior routing should not be reported again with the same passive recommendation.

Change the causal system, owner contract, runtime, validator or bootstrap when authority permits.

## Anti-governance-churn rule

Do not create a new policy, role, PASS or campaign just to demonstrate responsiveness.

A new permanent mechanism must identify:

- failure class;
- causal owner;
- enforcement;
- falsifier;
- rollback/supersession path.

Otherwise absorb the correction into an existing owner.
