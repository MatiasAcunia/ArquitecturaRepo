# L3 First Local Longitudinal Pilot

Status: future local acceptance exercise, not a pre-approved operation against any productive repository.

## Goal

Build a small synthetic retail inventory and sales CRUD over several actual Codex invocations. Evaluate both product functionality and the SDLC process honestly. The CLIENT can choose the fictional theme at dispatch; do not publish a customer-specific example in this public starter.

## Mandatory evidence first

Read the exact current v1.2 branch HEAD, successful GitHub CI, AGENTS.md, SECURITY.md, docs/25_V1_2_SECURITY_HARDENING_AUDIT.md, docs/26_L3_WINDOWS_PHYSICAL_ACCEPTANCE.md, docs/27_PROJECT_MODES_AND_STACK_SELECTION.md, docs/28_LONGITUDINAL_L3_TEST_PROTOCOL.md and state/V1_2_ACCEPTANCE_CRITERIA.json. Recheck native Windows/Codex Desktop, PowerShell, installed Codex Daily Control 2.0.2 exact physical binary and Goal/SQLite state. Current physical evidence prevails over older notes.

## Safety

Use one disposable local sandbox repo/DB and synthetic data, avoiding all active OWNER/ROBLOX/MUSIC/TRO/CTR repositories, Goals, Tasks, credentials, cloud services, ports and publication. Do not clone redundantly or create branches per bug. No paid APIs, real personal data, secrets export, destructive chat cleanup or cloud resource creation. Check disk and rollback before writing. A failing install must never delete unowned/live Product State.

## Longitudinal tasks

1. Snapshot initial environment, branch HEAD, tools, local permissions and rollback. Install the smallest justified scaffold in disposable folder and verify no unrelated mutation.
2. Run v1.1 validation and every v1.2 synthetic security, mode, telemetry, i18n and multi-process test. Document actual outputs and reproduce any failure rather than invent PASS.
3. Let I2 interview the CLIENT on users/workflows/constraints; persist canonical requirements, Product State, material interaction evidence and Technical Baseline in sandbox. Choose minimal stack and dated delivery plan.
4. Define one capability-level charter; I3 plans a tactical DAG and builds products, stock, sales lines, search and validation using a real persistent DB, migrations/recovery, tests and a minimal UI or CLI suitable to the machine.
5. Interrupt after real work, resume across multiple invocations, and show same campaign/Goal/Plan and exact authority. Inject stale charter, broken evaluator, ambiguous external effect, missing DB, corrupt artifact, configuration mismatch and model/task-loop falsifiers, then observe safe HOLD, root-cause hardening and recoverable evidence.
6. Exercise asynchronous/hybrid/team modes only if the real host/scheduler, leases and isolated test identities are verified. Otherwise mark HOLD, never simulated PASS.
7. Inspect strict monthly metadata report, disable only outbound with external_submission_enabled=false, disable all reporting with enabled=false and test invalid collector receipt using fake transport only. An upstream central collector is NOT configured in this starter; do not claim physical remote delivery.
8. Verify complete CRUD E2E, exact DB restart/migration, test evidence, independent review, human assessment, safe rollback and fresh-context reconstruction. No release/publication without separate authority.

## Continuous reporting

At meaningful transitions (not every token), capture exact HEAD/candidate, time, Goal/actor identity, intended and observed result, test/gate, interruption/recovery, failure class, evidence digest/ref, cost/disk and human intervention. Separate observation, inference and criticism. Critique excessive bureaucracy, wrong frameworks, poor agent behavior, incorrect tool configuration, model quality, false PASS, wasted commits/branches and client technical escapes.

## Terminal

Return one consolidated, sanitized longitudinal report: environment, timeline, CRUD features, tests, repeated-session evidence, 9 gate statuses PASS/FAIL/HOLD/NOT_APPLICABLE, causal root causes, independent reviewer result, rollback proof, privacy/collector truth and prioritized systemic corrections. Keep the same candidate for ordinary repair. Never merge/tag public 1.2.0 from synthetic CI alone.
