# Agentic SDLC FAQ (en)

[EN guide](README_en.md) · [Main README](../../README.md)

### 1. What is Agentic SDLC?

A reusable repository architecture for organizing software development with agents. It is not an autonomous app builder.

### 2. How do I start?

Fork or inspect the repository, start with read-only discovery, choose the smallest profile, and follow the installation prompt. A fresh scaffold begins in HOLD.

### 3. Can I adopt it into an existing repository?

Yes. Reconstruct actual code, data and authority first. Never overwrite application files or treat synthetic fixtures as product truth.

### 4. Do the four roles require four models?

No. CLIENT, I2 Planner, I3 Campaign Lead and optional I4 specialists describe decision rights, not fixed process counts.

### 5. Who decides sensitive changes?

The CLIENT retains product, subjective acceptance, publication, cost and sensitive-data authorization. I3 may not invent those permissions.

### 6. Are Goal planning and Codex Desktop supported automatically?

Not yet. v1.2 has optional Goal/Plan integrity code, but real per-invocation host integration is a separate physical acceptance gate.

### 7. Is Gemini required or charged by default?

No. The I4 provider path is optional and disabled until explicit permission, credential, quota and privacy checks. No default private-code upload.

### 8. Can it restart or delete my Codex chats?

Not from the starter itself. Codex Daily Control 2.0.2 is a separately tested reference; a safe real-host adapter is not yet accepted in v1.2.

### 9. What feedback is enabled by default?

One small monthly metadata report saved in your own GitHub Actions artifacts. It helps organize evidence and improve the starter. No automatic external transmission.

### 10. What data are excluded from feedback?

Code, conversations, project and repository names, paths, credentials, personal identifiers, requirements text, SHAs and unrestricted free text.

### 11. How do I change language or disable feedback?

Use --language auto|en|es|pt|fr|de|it|ja|zh; offline documentation follows the selected locale. Set enabled=false in the feedback config or use --no-feedback-workflow. GitHub's README remains static.

### 12. What is tested, and how do I report a problem?

v1.1 is stable. v1.2 is a draft candidate until independent physical gates pass. File a GitHub Issue with reproducible steps and redacted logs. Original source and documentation use MIT; third-party rights remain separate.
