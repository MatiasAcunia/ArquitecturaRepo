# Agentic SDLC FAQ (en)

[EN guide](README_en.md) · [Mini guide v1.4](MINI_GUIDE_en.md) · [Main README](../../README.md)

### 1. What is Agentic SDLC?

A reusable repository architecture for organizing software development with agents. It is not an autonomous app builder.

### 2. How do I start?

Fork or inspect the repository, start with read-only discovery, choose the smallest profile, and follow the installation prompt. A fresh scaffold begins in HOLD.

### 3. Can I adopt it into an existing repository?

Yes. Reconstruct actual code, data and authority first. Never overwrite application files or treat synthetic fixtures as product truth.

### 4. Do the four roles require four models?

No. CLIENT, I2 Planner, I3 Campaign Lead and optional I4 specialists describe decision rights, not fixed process counts.

### 5. Who decides sensitive changes?

The CLIENT retains product, subjective acceptance, publication, cost and sensitive-data authorization. I3 may not invent those permissions.

### 6. Are Goal planning and Codex Desktop supported automatically?

Not automatically. v1.4 includes portable Goal/Plan and authority checks, but native per-invocation Codex Desktop/Goals integration is a separate, unverified physical acceptance gate.

### 7. Is Gemini required or charged by default?

No. The I4 provider path is optional and disabled until explicit permission, credential, quota and privacy checks. No default private-code upload.

### 8. Can it restart or delete my Codex chats?

No. The starter itself does not restart, manage or delete native Codex chats. Any host adapter requires separate evidence and permission; no native chat lifecycle is certified by v1.4.

### 9. What feedback is enabled by default?

One small monthly metadata report saved in your own GitHub Actions artifacts. It helps organize evidence and improve the starter. No automatic external transmission.

### 10. What data are excluded from feedback?

Code, conversations, project and repository names, paths, credentials, personal identifiers, requirements text, SHAs and unrestricted free text.

### 11. How do I change language or disable feedback?

Use --language auto|en|es|pt|fr|de|it|ja|zh; offline documentation follows the selected locale. For all reporting, set enabled=false in the feedback config; --no-feedback-workflow only disables scheduling. GitHub's README remains static.

### 12. What is tested, and how do I report a problem?

Source version 1.4.0 is a release only when the [immutable v1.4.0 tag, ZIP and checksum](https://github.com/MatiasAcunia/ArquitecturaRepo/releases/tag/v1.4.0) are published and verified; v1.3.0 remains available. Portable Linux/Windows checks do not certify native agent hosts or third-party usability. File a GitHub Issue with reproducible steps and redacted logs. Original source and documentation use MIT; third-party rights remain separate.

### 13. Can asynchronous, team and non-code AI modes be combined?

Yes, as configuration dimensions. Only a real authorized host and proven leases, ownership, recovery, rights and human acceptance allow execution. Default SMALL remains synchronous/solo. I2 stores your requirements and stack in the existing repo; commit and branch mania are prohibited. Outbound anonymous feedback is preference-on only after an approved receiver exists, and can be disabled.
