# Agentic SDLC FAQ (ja)

[JA guide](README_ja.md) · [v1.4 ミニガイド](MINI_GUIDE_ja.md) · [Main README](../../README.md)

### 1. Agentic SDLC とは何ですか？

エージェントによるソフトウェア開発を整理する再利用可能なアーキテクチャです。どんなアプリも自動で完成させるサービスではありません。

### 2. 使い始めるには？

リポジトリを確認または fork し、読み取り専用の調査から始め、最小のプロファイルで導入してください。新規 scaffold は HOLD で始まります。

### 3. 既存のリポジトリにも導入できますか？

はい。実際のコード・データ・権限を先に調べます。アプリのファイルを勝手に上書きしたり、サンプルの状態を正しい状態と見なしたりしません。

### 4. 四つの役割には四つのモデルが必要ですか？

いいえ。CLIENT、Planner I2、Campaign Lead I3、I4 専門家は責務の区分であり、固定のプロセス数ではありません。

### 5. 機密操作は誰が承認しますか？

製品方針、主観的な受入れ、公開、費用、機密データについては CLIENT が権限を持ちます。I3 は許可を推測しません。

### 6. Goals と Codex Desktop は自動連携していますか？

自動では連携しません。v1.4 には移植可能な Goal/Plan・権限チェックがありますが、Codex Desktop/Goals の呼び出し単位のネイティブ連携には別の実機検証が必要です。

### 7. Gemini は必須・標準課金ですか？

いいえ。明示的な有効化、認証情報、利用枠、プライバシーの確認までは無効です。非公開コードを既定で送信しません。

### 8. Codex のチャットを再開・削除しますか？

いいえ。starter 自体は Codex のネイティブチャットを再開、管理、削除しません。ホスト用アダプターには独立した許可と証拠が必要で、v1.4 はこの機能を認証していません。

### 9. 既定のフィードバックは何ですか？

月一回、プロジェクト自身の GitHub Actions artifacts に少量のメタデータを保存します。改善には役立ちますが、外部へ自動送信しません。

### 10. 収集しない情報は？

コード、会話、プロジェクト名・リポジトリ名、パス、秘密情報、個人識別子、要件本文、SHA、自由記述です。

### 11. 言語変更と無効化の方法は？

--language auto|en|es|pt|fr|de|it|ja|zh を使います。全レポートの停止には enabled=false を設定します。--no-feedback-workflow はスケジュールだけを無効にします。GitHub の README は静的です。

### 12. 何が検証済みで、問題はどこへ報告しますか？

**v1.4.0 は公開済みです**。[バージョン付きタグ、ポータブル ZIP、SHA-256 チェックサム](https://github.com/MatiasAcunia/ArquitecturaRepo/releases/tag/v1.4.0)が提供されています。ダウンロードしたファイルを検証してください。`main` ブランチには新しい文書が含まれる場合があり、旧版 v1.3.0 も引き続き利用できます。Linux/Windows のポータブルテストはネイティブのエージェントホストや第三者の使いやすさを保証しません。再現手順と秘密情報を除いたログを GitHub Issue に記載してください。元のコードは MIT ライセンスです。

### 13. 非同期・チーム作業・非プログラミング AI を組み合わせられますか？

はい。これらは独立した設定軸です。実際の実行には検証済みホスト、権限、復旧、データ利用許可が必要です。SMALL は簡潔な構成のままです。I2 は要件と技術選択を正規リポジトリに保存し、無意味なコミットやブランチを禁止します。外部フィードバックは検証済み送信先がない限り送れず、無効化できます。
