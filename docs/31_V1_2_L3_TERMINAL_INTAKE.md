# L3 terminal intake template (private/local only)

This template describes what evidence to request, NOT a mandate to rerun a currently executing L3. It is not a second campaign or release-authority file. The local physical report may contain private source paths and hashes; **never commit it directly to the public starter**.

## Identification

- Pilot: CRUD / EXISTING_REPOSITORY / RELEASE_CHALLENGE.
- Exact starter candidate/ref, exact private adopter source/head (if permitted), host OS/build, shell, Python/DB/Git, Codex native host and Codex Daily Control 2.0.2 actual observed build.
- Runtime authority: CLIENT, I2, one continuing I3 identity, optional I4 reviewer; source of each permission. No assumed authority from Git commits.
- Observation window and actual number of distinct Goal invocations, interrupted/continued sessions, checkpoints, reviewer rounds and provider calls. Use NOT_TESTED rather than fabricating zeros.

## Gate matrix

| Gate | Expected and negative falsifier | Observed real vs synthetic | Exact evidence location + hash | Actor/independent reviewer | PASS / FAIL / HOLD / NOT_APPLICABLE |
|---|---|---|---|---|---|

A PASS needs physically retrievable source/artifact/host proof, not a summary statement. HOLD identifies missing evidence and a bounded next legal action. A failed run is not a gate PASS merely because the model later proposed a fix.

## Compact chronological evidence

Record meaningful state changes (not tokens or every commit): timestamp, initial/final product state, exact candidate identity, actual input/fault injected, observed reaction, recovery/rollback readback, relevant resource and privacy/cost gates. Preserve source provenance. If the project is a music/media or other artifact pipeline, distinguish technical byte integrity from perceptual/editorial/legal/public-release acceptance.

## Process critique

Quantify first-install steps, time to useful proof, extra branches/worktrees/clones, unneeded tool/model calls, agent error patterns, incorrect configuration, repeated review churn, DB/asset access friction, manual CLIENT technical intervention, disk/cost and first-run documentation surprises. Compare with a simpler project baseline; call out overly invasive governance.

## Root-cause findings

For each material defect: stable class, P0/P1/P2, reproduction and expected/observed, causal owner (starter vs host vs adopter project vs environment vs missing evidence vs agent behavior vs UX vs privacy), changed surfaces, downstream invalidations, successful falsifier, independent evidence and next owner. Consolidate duplicates.

## Terminal disposition

Use one of:
- SUPPORTED_FOR_RELEASE_REVIEW (never automatically authorizes merge);
- SAME_CAMPAIGN_HARDENING_REQUIRED;
- PHYSICAL_HOST_OR_EXTERNAL_HOLD;
- STRATEGIC_CHARTER_INVALIDATION_ESCALATION.

Provide one table of gate outcomes and at most three highest-impact systemic corrective actions, with rollback and sanitized public-digest readiness. Distinguish measured behavior from speculation. Never post raw private L3 evidence to public GitHub or telemetry.
