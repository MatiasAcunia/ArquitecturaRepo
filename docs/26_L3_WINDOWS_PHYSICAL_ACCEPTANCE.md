## Pilot gates (each with real evidence)

1. **Install and rollback**: clean Windows 10/PowerShell 5.1 fixture, synthetic project, parser/probe, check a failed upgrade restores prior state and doesn't follow symlinks or delete non-starter data.
2. **Goals**: one disposable Goal with canonical charter and plan; initial and subsequent invocation reentry with live digest, exact remote and authority; reject changed/stale/missing theory, negative currentness and short-context reentry.
3. **Tactical plan**: I3 uses its real planning tool when available, performs in-envelope DAG changes, journals checkpoints and notices an active-progress review due without terminating the campaign.
4. **I4 Gemini**: public/synthetic minimal data only, verified nonbillable quota and provider policy, two distinct-evidence consultations delivered to the same Goal I3 and explicitly accepted/rejected with tests; failure/quota/timeout and injection falsifiers.
5. **Codex Daily Control 2.0.2**: verified ordinary 300-minute quota permission, exact native Goal identity, Resume of usage-limited only, refusal of paused/blocked/budget-limited/complete, native keepalive behavior; no UI clicking as final Resume authority.
6. **Daily close**: one disposable transcript; complete local export, checksum and cloud API readback (not filesystem illusion), exact final marker, no chat deletion if active writer, external readback mismatch or missing receipt. Destructive cleanup requires separate proof/consent.
7. **Five Tasks OWNER (isolated)**: provision only when explicit user approves, verify five logical roles, active schedules/returns, suspension precedence, mutual recovery check and no sixth supervisor; verify existing task IDs aren't accidentally reused.
8. **Feedback/privacy**: monthly local report default, no secrets or free text, first-run disclosure and switch off; two-key external submission to an approved test collector, TLS/receipt hash mismatch and shutdown.
9. **Unrelated adoption**: one external nonportfolio synthetic or volunteer repository; protect application files, compare before/after hashes, prove no extra clones, no surprising LLM spend or external mutation.

## Evidence format

For each gate: exact commit and host/build, setup/constraints, executed steps, expected result, observed result and hash/source path, negative/falsifier outcomes, safety/privacy/cost observations, rollback proof, independent reviewer and disposition. No screenshots or copied commands alone are PASS. Persist concise receipts, not giant chat transcripts, and publish a sanitized summary only after any sensitive identifiers are removed.

## End

If a physical test fails, keep v1.1 stable, isolate the root cause, fix within the same v1.2 candidate, rerun its regressions and repeat only the relevant real-host gate. Do not create duplicate release branches or declare acceptance from simulated tests. Return a consolidated L3 report with evidence-backed PASS/HOLD per capability and proposed 1.2.x release decision.
